# 업적

`runs`에서 전부 파생 계산한다 — 테이블도, 컬럼도 늘리지 않는다
([data-model.md](data-model.md)의 설계 원칙 1과 같은 이유다). 기록만 동기화되면
어느 기기에서든 같은 결과가 나온다.

판정에 쓰는 값은 런 한 건이 가진 것뿐이다:
`smcId, smcUpgrade, playedAt, outcome, note, deckers[{deckerId, playerName}],
objectives[{cycleNo, objectiveId, security, result, isFinal}]`.

## 오픈과 히든

**숫자를 쌓아 올리는 건 오픈, 상황이 우연히 걸리는 건 히든.** 진행도 바가 의미
있으면 오픈이고, 진행도를 보여주는 순간 조건이 새면 히든이다.

- **오픈**: 이름·조건·진행도를 처음부터 보여준다. 타일 하나 = 업적 하나(티어 없음).
- **히든**: 잠긴 동안 목록에 **개별로 나타나지 않는다.** 이름도, 아이콘도, 조건도,
  진행도도 없다. `???` 자리표시 타일도 깔지 않는다 — 수십 칸이 죽은 칸이 된다.
  드러나는 건 **개수뿐**이다(게이지의 `히든 n/N`, 요약 카드의 남은 수).
  해금되면 그때 이름과 조건이 함께 공개된다.

색으로도 가른다 — 오픈은 `--gold`, 히든 해금은 `--ghost`.

## 구현 메모

- **판정은 `src/lib/achievements.js`에 있다.** 화면에 두면 테스트가 붙지 않는다.
  오픈은 `{ metric, goal }`, 히든은 참/거짓 플래그다. 보드·조합 같은 공통 파생값은
  [`src/lib/derive.js`](../src/lib/derive.js)에서 가져온다.
- **해금 시각이 없다.** 업적이 `runs` 파생이라 "언제 땄는지"가 남지 않는다
  ([data-model.md](data-model.md) 참고). 해금 연출은 로컬 `meta`의
  `seenAchievements:{userId}`에 본 id를 적어두고 새로 뜬 것만 띄운다. 동기화
  커서와 같은 방식으로 계정별로 나눠 두므로, 계정을 바꾸면 그 계정 기준으로 다시 센다.
  기기마다 따로 뜬다.
- **처음 보는 칸에는 조용히 도장만 찍는다.** 이미 84칸을 깬 사람에게 토스트 수십 개를
  쏟지 않기 위해서다. 한 번에 4개 이상이 열리면 이름 대신 개수 한 줄로 합친다 —
  방금 친 판이 아니라 동기화로 들어온 것들이라 축하가 어색하다.
- **`undo-5`는 두 곳을 더한다.** `allRuns()`가 tombstone을 걸러내므로 삭제 수는
  `db.runs` 원본에서 세고, 서버에 올라간 적 없어 물리 삭제된 런은 `deleteRun`이
  `meta.purgedRunCount`에 횟수만 남긴다. 한 런은 둘 중 한 경로만 타므로 겹치지 않는다.
- **농담은 번역이 아니라 다시 쓰는 것이다.** `말잇못`·`밥은 먹었니`·`1인 4역`은
  한국어에서만 성립한다. 조건은 언어 무관하니 en/de는 그쪽 관용구로 **새로 짓는다.**
  직역하면 셋 다 죽는다.
- 화면 구성은 [ui-draft.md](ui-draft.md)가 아니라 별도 `/achievements` 라우트다.
  프로필에는 `.linkrow` 한 줄만 남긴다.
