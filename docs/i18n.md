# 다국어 (한국어 · English · Deutsch)

Deckers는 판본마다 카드 이름과 본문이 다르다. 그래서 번역 대상이 **두 종류**이고,
성격이 완전히 다르므로 파일부터 나눠 둔다.

| | 위치 | 성격 |
|---|---|---|
| **UI 문구** | `src/i18n/{ko,en,de}.json` | 우리가 쓰는 글. 자유롭게 의역 가능 |
| **게임 콘텐츠** | `src/data/content/{ko,en,de}.json` | 실물 카드에 인쇄된 문구와 일치해야 함 |

## DB는 다국어와 무관하다

`runs`에 저장되는 건 `smc_id` / `objectiveId` / `deckerId` / `security` / `outcome` —
전부 언어 무관 id다. **언어를 추가해도 스키마 변경이 없다.**

덕분에 언어를 바꿔도 기존 기록이 그대로고, 독일어를 쓰는 사람의 기기와 내 기기가
같은 기록을 각자 언어로 본다. **이 원칙은 깨지 말 것** — 표시용 문자열을 기록에
저장하는 순간 무너진다.

`reports.context`에는 `locale`이 함께 실린다(스키마 변경 불필요 — jsonb).

## 뼈대와 콘텐츠

`src/data/gameData.js`에는 언어와 무관한 값만 남긴다.

- SMC: `id`, `difficulty`, `cycles`
- 덱커: `id`, `color`
- 카드: `id`, `security`, `code`, 배열 순서
- `DECKER_COLORS`, `SECURITY_COLORS`

**`code`(BLK, DDF…)는 일부러 언어 무관이다.** 미션 보드(84칸)의 열 머리글이라,
언어를 바꿔도 레이아웃이 흔들리지 않는다. 현지 이름은 툴팁과 하단 범례에서 보여준다.

**`tier`는 데이터가 아니다.** `difficulty`에서 파생되는 표시용 라벨이라
`gameData.tierKey()` + `game.tier.*` 문구로 처리한다.

## 업적 문구는 번역이 아니라 다시 쓰는 것이다

업적 이름·조건은 `achievements.list.<id>.{name,desc}`에 있다
([achievements.md](achievements.md)). **조건(`desc`)은 언어와 무관한 사실이라 번역이지만,
이름(`name`)의 상당수는 농담이라 직역하면 죽는다.**

`말잇못` → `Speechless` / `Sprachlos`, `밥은 먹었니` → `Did You Eat?` / `Schon gegessen?`,
`엄마한테 혼났다` → `Grounded` / `Hausarrest`.

판정은 세 언어에서 동일해야 한다. 예컨대 웃음만 적힌 메모를 잡는 `lol-only`는
`ㅋㅎ`·`lol`·`haha`를 한 정규식에 담는다 — 조건이 언어를 타면 같은 기록이 기기마다
다른 업적을 준다.

## 폴백

콘텐츠 폴백은 **필드 단위**이고 폴백 로케일은 `en`이다.

```
ko.json 에 name 이 없으면 → en.json 의 이름
ko.json 에 goal 이 있으면 → 그대로 사용
```

그래서 한국어판 카드명을 아직 안 넣었어도 영어 이름이 나오고 본문만 한국어로 보인다.
판본을 하나씩 채워 나갈 수 있다. `en.json`에는 **모든 id의 `name`이 반드시 있어야 한다.**

카드 본문이 비면 `FlipCard`가 "실물 카드 참고"로 처리하므로 앱은 정상 동작한다.

현재 상태: 카드 본문 **6 / 40**(한국어만). `de.json`은 빈 스캐폴드.

## 코드에서 쓰기

```js
import { useT } from '../i18n'
import { cardName, smcName, cardText } from '../i18n/content'

const { t, locale, setLocale } = useT()
t('history.runs', { count: 3 })     // {count} 보간 + 복수형
cardName('gold-hackman')            // 현재 언어의 카드 이름
```

로케일은 **React 컨텍스트가 아니라 모듈 상태**다. `ErrorBoundary`는 Provider보다
바깥에 있어야 하는데(Provider가 터져도 잡아야 하므로), 컨텍스트로 만들면 크래시
화면만 번역이 안 된다. 그래서 `t()`는 어디서든(React 밖에서도) 부를 수 있고,
`useT()`는 `useSyncExternalStore`로 언어 변경 시 다시 렌더할 뿐이다.

복수형은 `Intl.PluralRules`를 쓴다. 값이 `{ "one": …, "other": … }` 객체면
`count`에 맞춰 고른다. 한국어는 형태가 하나라 항상 `other`.

## 로케일 저장

`localStorage['deckers.locale']`. **동기화하지 않는다** — 언어는 기기별 취향이고,
같은 계정을 다른 사람이 다른 기기에서 열 수 있다.

Dexie가 아니라 localStorage인 이유는 **동기 읽기**라 첫 페인트에 언어를 알 수 있어서다.
Dexie(비동기)면 잘못된 언어가 한 프레임 번쩍인다. 접근 자체가 예외를 던지는 환경이
있으므로 `try/catch`로 감싸고, 실패 시 `navigator.languages` 추정으로 넘어간다.

## 번역할 때 지킬 것

**문구 길이 예산.** 좁은 슬롯은 번역 길이로 깨진다. 독일어가 특히 길다.

| 슬롯 | 예산 |
|---|---|
| `nav.*` (하단 탭 6개) | **8자 이하** |
| `newRun.success` / `newRun.fail` | 6자 이하 |
| `game.security.*` (카드 탭 4개) | 12자 이하 |

통제 불가능한 건 **카드 이름** 하나뿐이다(게임이 정한 값). 유일하게 좁은 칸인
`.deck-strip .mini`는 세로 쌓기 + 줄바꿈을 허용해 대응했다.

**서체.** IBM Plex Mono와 Chakra Petch에는 한글 글리프가 없다. `--mono` 스택 끝에
`IBM Plex Sans KR`을 넣어 라틴은 모노, 한글은 지정 서체로 떨어지게 했고,
라틴용 자간이 한글에 걸리지 않도록 `:lang(ko)`에서 `letter-spacing`을 되돌린다.
`<html lang>`은 `syncDocumentLang()`이 설정한다.

**날짜.** `src/lib/format.js`가 `Intl.DateTimeFormat`으로 처리한다.
독일어권은 `D.M.` 순서라 하드코딩하면 안 된다.
